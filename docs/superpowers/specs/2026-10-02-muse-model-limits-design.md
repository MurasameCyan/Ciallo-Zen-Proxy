# Muse 模型输出上限与能力提示设计

日期：2026-10-02
分支：`beta`

## 目标

修复 Muse Spark 1.3 在 Claude Code 中因过大输出预算收到 400 的问题；成功的真实请求能及时纠正模型可用状态；在模型胶囊悬停提示中提供上下文上限、最大输出和思考等级。

不改变模型选择、模型探针频率、节点轮换、重试策略或面板整体布局；不增加依赖。

## 证据与现状

- 捕获的 Anthropic 请求包含 `max_tokens: 1048576`。该模型目录记录 `maxOutputTokens: 131072`。
- 对线上同一模型发送最小对照请求：`max_tokens: 1048576` 返回 400；改为 `131072` 返回 200。失败响应是上游通用参数错误。
- 模型状态探针对非传输类 5xx 保存 `unknown` 六小时；真实请求成功目前不会更新探针状态。因此一次 503 可让模型胶囊继续显示未知，直到后续探测。
- `/api/status` 已提供模型上下文、可用性和 models.dev 元数据；胶囊现有 `title` 只在有错误或名称溢出时使用。

## 方案

采用已批准的方案 A：根据已知输出上限钳制出站预算；真实上游成功结果更新该模型为 `available`；用原生 HTML `title` 显示能力详情。保留未知与不可用的区别，不缩短 503/429 探针间隔，也不因参数类 400 把模型判为不可用。

`maxOut` 的有效实测值优先；没有时回落到 models.dev `maxOutputTokens`。两者都无有效值时不改写客户端预算。出站预算已经低于上限时保持原值；不凭空增加请求预算。

## 行为

### 输出预算

对出站 Responses 请求，若存在正的 `max_output_tokens` 且能取得模型输出上限，将其限制到 `min(请求值, 模型上限)`。Anthropic Messages 和 Chat 输入转换到 Responses 时沿用这一规则；原生 Responses 请求也应用同一上限。非 Responses 上游协议不受影响。

上下文上限与输出上限是不同字段；本改动只钳制输出预算，不截断输入上下文，也不把 `max_tokens` 当作上下文上限。

### 可用状态

只有已确认的上游成功结果才能调用 `markAvailable(model)`，并清除旧探针错误与重试时间。现有明确模型下线错误仍可调用 `markUnavailable`。参数错误、上游 5xx、取消和传输失败不得被当成成功；失败分类及探针节奏保持现状。真实成功以模型实际接受请求为准，无需新增探测流量。

### 悬停提示

每个模型胶囊都设置标题提示，至少包含：

- 上下文上限：使用当前 `/api/status` 的模型上下文值；缺失时显示“未知”。
- 最大输出：优先显示实测 `maxOut`，其次显示 models.dev `maxOutputTokens`；缺失时显示“未知”。
- 思考等级：有严格实测列表时列出实际支持等级；宽松模型显示实测顶档并注明等级未枚举；没有实测记录时显示“未探测”。
- 当前探针状态；存在探针错误时追加错误摘要，不将参数错误误标成模型不可用。

继续保留现有 `aria-label` 状态信息和溢出文本的键盘访问行为。未知状态仍是未知，不通过颜色或文字宣称可用。

## API 与兼容性

扩展现有 `/api/status` 模型能力数据以提供安全、精简的输出上限与思考等级记录；沿用现有 `ctx` 和 `metadata`。不新增端点，不返回能力缓存中的无关内部字段。旧缓存或缺失能力记录按“未知/未探测”呈现，不阻止服务启动。

## 验证

- 单测：大于上限的 Responses 输出预算被钳制；低于上限的预算不变；无已知上限时不变；对非 Responses 方言不改写。
- 状态测试：已确认的真实成功把先前 `unknown`/错误状态改为 `available` 并清除错误；普通失败和取消不改为可用。
- 前端测试：标题包含上下文、输出上限、思考等级和探针错误；缺字段使用明确的未知文案；ARIA 与溢出键盘行为保持。
- 线上烟测：同一 Muse 请求在 1M 预算下仍应由网关限制到 `131072` 并成功；比上限小的预算保持原值。

## 文档

更新 README 的模型清单/能力说明：模型卡片悬停详情的数据来源、未知值含义，以及模型输出预算会按已知上限限制。说明成功真实请求也会刷新可用状态；失败探针仍不等同于模型下线。

## 验收标准

1. Muse Spark 1.3 的 `1048576` 输出预算不再原样发给上游；在已知 `131072` 上限时发出的输出预算不超过该值。
2. 实际成功请求后，模型可用状态显示 `available`，而无效参数失败不产生虚假的成功状态。
3. 悬停模型胶囊可读到上下文、最大输出、思考等级及状态；缺失能力明确显示未知/未探测。
4. 现有节点探测频率、429/5xx 调度、模型状态语义及无依赖约束保持不变。
